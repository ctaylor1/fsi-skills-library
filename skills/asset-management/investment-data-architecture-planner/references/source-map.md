# Source map and provenance

The executable method is governed by the supplied institutional data dictionary, license and permission evidence, source-system export history, shared architecture review and monitor evidence. Require exact source locators and versions; examples in this package are synthetic and cannot substitute for these records.

| Claim | Required source |
| --- | --- |
| Grain, identity namespace, semantic unit/currency, transformation | Versioned source dictionary and accountable field owner |
| Portfolio/account/security/benchmark relationships | Authoritative source keys or explicitly reviewed crosswalk; no fuzzy joins |
| As-valid and as-known history/corrections | Dated versioned export or change log with both intervals; retain earlier assertions |
| Licensed purpose, audience, principal, term, retention | Operative institution-reviewed agreement and entitlement policy; legal interpretation remains with owner |
| Access at read time | Fresh approved gateway response bound to request and principal; stored observation remains historical evidence |
| Operating monitor result | Dataset/snapshot-bound observed measurement, date, unit, threshold and incident owner |
| Component/interface/cost assessment | Shared owner's native original and reconstructed output, same object/date/currency |

This package introduces no regulatory deadline or jurisdiction standard as an assumed fact. Obtain current authoritative obligations when those are needed for the user's actual institution. Data provenance and software reproducibility remain distinct from vendor authentication, completeness and professional acceptance.

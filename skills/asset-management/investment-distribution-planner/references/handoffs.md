# Handoffs and ownership

Triage into this workflow only for the stated business method. Route related institutional-proposal-responder work to that installed package with the original scope, request ID, as-of/knowledge cutoff, explicit open issues and source access restrictions. Route specialist investment-product-lifecycle-planner analysis to its own method rather than deriving unsupported conclusions here.

Outputs are native internal evidence packets. A consumer must obtain the detached original, invoke this package's actual output validator, and explicitly map native fields into its own validated input schema. Envelope hashes or a supplied approval alone are insufficient. Do not erase omissions, currency/book/period differences, client restrictions or unresolved issues during mapping.

A planned handoff is a practitioner recommendation; no API call, notification, recurring task, approval or external execution is performed.

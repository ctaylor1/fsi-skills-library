# Investment workflow route review

Use this as a separate practitioner-readable report. Do not add these narrative fields
to the deterministic native JSON. Retain native output and its detached original input
for validation.

- Request: supplied request ID, real as-of date, requested action.
- Subject: supplied type and identifier; identify any scope clarification required.
- Requested jobs: each declared intent and its actual professional owner.

Keep institutional manager diligence and institutional RFP limitations explicit. For a
planned primary, state that the requested capability is not implemented. For an
out-of-domain job, identify its owner without claiming that owner's workflow ran.
For an execution request, state that execution is unsupported. Do not turn an absent
inventory into an installed claim or treat containing-package installation as proof
of native-mode compatibility.

Unresolved issues: reproduce all supplied issues, then distinguish any additional
review questions in this separate narrative. Do not silently close an upstream issue.

Validation record: original input digest, route ID, output-validation result, current
route/capability version and any separately validated handoff evidence. Source truth is
unverified; hashes bind supplied values and do not authenticate sources.

Authority: review plan only. No workflow launch, action, authority grant or external
delivery occurred. Human review is required. Identify the actual professional owner
and remaining acceptance work without fabricating their approval.

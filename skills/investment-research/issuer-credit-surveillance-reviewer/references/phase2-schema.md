# Native schema

This is the only live intake contract as of package 0.4.1. Legacy requests/packets are rejected at every public entrypoint; see [reviewed migration](schema.md).

All Phase 2 inputs carry schema_version=ir-phase2/1.0, request_id,purpose=internal-research,audience=internal-review,subject{type,id,issuer_id for security},as_of,use_on,knowledge_cutoff,information_barrier,sources[],top-level evidence_refs[],unresolved_issues[]. Use an aware timestamp cutoff for intraday spread comparisons; a date-only cutoff cannot support that comparison. Every row citation must be nonempty, registered and also declared at top level for source permission/time gating. Supplied future or ineligible evidence withholds the result projection. The example is synthetic; no entitlement or authenticity is asserted.

`issuer_profile` is nonfinancial-corporate. `prior` and `current` are reported financial observations, with explicit currency,unit,accounting_basis,consolidation_scope,period,evidence_refs; nullable EBITDA,gross_debt,unrestricted_cash,interest_expense,mandatory_capex,available_committed_facilities,near_term_maturities; boolean maturity_inventory_complete. Each period must end on or before both economic `as_of` and the knowledge-cutoff date (UTC for an aware cutoff). Forecast/scenario financials are unsupported. Prior must precede current with matching calendar,currency,unit,basis,scope and comparable duration. `thresholds` has leverage_increase_x,coverage_decline_x,spread_widening_bps. `events[]` carries kind,text,evidence_refs.

Optional `prior_spread`/`current_spread` carry observation_id,security_id,issuer_id,currency,basis,spread_bps,evidence_refs and an aware intraday `observed_at` timestamp (for example `2026-10-20T16:00:00Z`). These rows are assertions to reconcile, not the evidence ledger. An issuer request requires their issuer to equal `subject.id`; a security request requires their security to equal `subject.id` and issuer to equal `subject.issuer_id`.

`spread_evidence[]` contains structured observations extracted from supplied evidence blocks, independently of the assertion rows. Each selected record requires observation_id,role=`spread-observation`,security_id,issuer_id,currency,basis,spread_bps,observed_at and `evidence_ref{source_id,source_version,locator}`. Select exactly one record by each row's observation_id. Duplicate selected IDs or multiple records for the selected security/currency/basis/observation instant are ambiguous even when their values agree or their IDs differ. The asserted identity, basis, finite value and observation instant must match the record; no tolerance or asserted value override is used. Equivalent aware timestamp representations refer to the same instant.

The evidence reference must match a registered source's ID, exact version and exact `source.locator` identifying the supplied evidence block. Register a precise subsection as its own source block when needed; a mutually copied child/arbitrary locator does not establish a registry match. Each asserted quote has exactly the matching source_id/locator citation, also declared in top-level evidence_refs. The source must be `market_data`, explicitly list both security and issuer in subject_ids, and pass the common research-cutoff, permission, audience, purpose, barrier and use-date gates. A source kind label alone cannot supply missing observation contents. A financial-statement source cannot serve as a quote source even when the ledger and assertions match.

`instrument_evidence[]` requires one record for the selected security with role=`security-issuer-mapping`,security_id,issuer_id,currency,valid_from,valid_to and evidence_ref of the same shape. Both quote observations must agree with this mapping and fall within its inclusive validity period. A calendar-date bound is interpreted against the observation's UTC calendar date; an aware timestamp bound compares instants. Do not manufacture a midnight instant for a date-only bound. Missing bounds, multiple mappings for the selected security or a current-only mapping that does not cover the prior quote withhold the comparison. Mapping sources may be market_data,filing,credit_document or issuer_release; they must explicitly cover both security and issuer, match the precise registered source block/version, and be eligible at the research cutoff. Mapping knowledge may legitimately follow a historical quote. Foreign-currency bonds are supported when the mapping and both quotes agree; no FX conversion or comparison to financial-statement amounts is implied.

A comparison also needs explicit `spread_freshness_policy{max_current_age_hours}`: a finite nonnegative number of elapsed hours measured from the current observation to `knowledge_cutoff`. There is no default institutional freshness limit. Zero permits only an observation exactly at cutoff. The age limit applies to the current quote, not the intentionally historical prior quote.

Comparable quotes require exact security/currency/basis equality; strictly increasing observation instants; both instants on or before cutoff; and observation UTC calendar dates on or before economic `as_of`. Each quote's cited source/version must carry an aware `known_at` timestamp on or after that quote's observation. Source publication may legitimately follow observation and must remain eligible under the common cutoff gate. Date-only source knowledge cannot establish this ordering and is not promoted to midnight.

Missing observations/policy/evidence/mapping, claim/evidence disagreements, conflicting records, unsupported evidence roles, insufficient source time precision, stale or unordered/future observations, and quote-key mismatches produce a partial result with `spread_change_bps: null` and no spread-widening alert. Valid financial metrics remain available. A supplied malformed/naive observation timestamp, malformed inventory/field or malformed/negative policy is an input error. Absence of both optional spread rows requests no comparison. Unrelated unselected inventory records cannot select themselves or contribute to the returned evidence context. Every source explicitly declared used at top level still participates in the common whole-projection source gate, including sources only associated with unused records. `source.known_at` never substitutes for `observed_at`.

`results.spread_reconciliation` is `not-requested`, `withheld` or `reconciled-supplied-evidence`. Only a reconciled comparison retains the exact selected structured observations and mapping, including source version/block and effective period. Withheld context has empty observations and null instrument_mapping. The delta is computed from selected evidence values using exact rational arithmetic on their JSON decimal representations, then emitted as a finite JSON number. Output reconstruction binds the entire ledger, original and returned context. These checks establish internal supplied-evidence consistency, not authenticated source contents, completeness of extraction, entitlement or institutional acceptance. Do not create an evidence ledger by copying unsupported assertions.

See the paired JSON fixtures under evals/files; the separately retained original is mandatory for output reconstruction.

# Controls and professional responsibility

Accountable function: **Regulatory Compliance / Control Framework Owner**. Risk tier R3; offline read-only decision support.

Human owners retain regulated judgment, mandate acceptance, legal interpretation, exceptions, approval and actions. A source label, reviewer string, status field, hash or valid output does not confer authority. Do not approve a program, certify compliance, release a product, alter a system of record, file, notify or grant a permission through this package.

Fail input validation before calculating malformed records, non-finite values, duplicate identities, unsupported formats and invalid relationships. Material unknown/missing/conflicting/stale facts cannot support a favorable conclusion. Exact detached-output reconstruction rejects altered findings, added fields, raw source embedding and self-rehashed substituted input.

Management self-assessment, operational QA, second-line oversight, statutory independent testing, model validation and third-line audit are separate mandates. Independence requires actual mandate/conflict evidence and human adjudication; a role name does not establish it.

Minimize data and record source-specific classification, permitted audience, purpose, legal privilege, SAR restrictions, MNPI and retention requirements only where the actual source/use warrants them. Native IDs should avoid personal identifiers. Keep restricted raw evidence outside the result. A handoff preserves the same source context and requires receiver validation; it is not an execution instruction.

Tests establish bounded software behavior with synthetic inputs. Professional, institutional, source and operational acceptance is not established by these packages.

# Native handoffs and adjacent boundaries

Receive insurer capital analyses from `insurance-capital-solvency-analyzer` and source scenario losses from `catastrophe-scenario-analyzer`, mapped into the actual ORSA capital/scenario schema after professional review. Use `liquidity-risk-scenario-analyzer` for detailed cash-flow modeling and `enterprise-risk-assessment-builder` for enterprise-wide risk assessment beyond insurer ORSA. Send an explicitly scoped evidence request to `audit-evidence-packager` for audit preparation. Carry materiality rationales, scenario/horizon mappings, capital/liquidity bases, quantitative differences, narrative sources and open governance decisions. Never turn a complete evidence packet into an ORSA filing or approval instruction.

Use the portable make_handoff/validate_handoff contract when exchanging a structured packet: retain source artifact, populate receiver-native data, propagate unresolved issues and validate against the actual receiver validator. Requested output is review-only and authority_granted stays false. If capacity, represented party, object, jurisdiction or line changes, supply exactly one reviewed source-bound context mapping as described in insurance-foundation.md; a renamed entity is not a valid mapping. Route back to the source owner when identifiers or bases disagree. Avoid duplicate execution of the neighboring workflow.

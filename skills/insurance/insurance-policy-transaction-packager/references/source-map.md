# Native source map

Common top-level fields: case_id, as_of, context{capacity,represented_party,object_id,jurisdiction,line_of_business}, sources[{source_ref,version,as_of?}], explicit unresolved_issues[], optional upstream_artifacts[], and data. Dates are YYYY-MM-DD. Source IDs must resolve uniquely.

`data.policy`: policy_id, version, status, jurisdiction, line_of_business, currency, effective_from/effective_to, values object, source_refs. `data.request`: request_id, policy_id, expected_policy_version, requested_by, transaction_type, effective_date, changes[{field,before,after,source_refs}], source_refs. `authority`: actor_id, policy_id, actions, effective_from/to, source_refs. `rule_profile`: profile_id/version/source_refs/effective_from/to/jurisdictions/lines_of_business plus transactions[action] with allowed_statuses, allowed_fields, required_documents, required_recipients, minimum_notice_days, notice_day_basis calendar, backdating_permitted. `documents`: document_id/kind/version/policy_id/policy_version/source_refs. `notices`: recipient/planned_send_date/source_refs. `premium_effect`: signed amount/currency/basis written-premium-change/source_refs. Explicit pending_inventory_complete and pending_transactions[{request_id,policy_id,status,source_refs}]. An empty inventory is an assertion needing source-owner review, not verified external truth.

Use controlled policy/PAS, billing/cash, authority and jurisdiction-rule evidence. The scripts fetch no source and do not authenticate it. Locate each asserted fact in the supplied source before mapping JSON.

Supported context/policy line values are exactly `pc`, `life`, and `annuity`; product-specific administrative rules must be supplied in the matching profile. Output `proposed_changes.before` comes from the current policy snapshot, with `before_known` distinguishing a missing field from a known null. `requested_before` preserves the original request and `before_matches_request` identifies a conflict; `policy_source_refs` attributes the current value separately.

# Ownership and native handoffs

- `catastrophe-exposure-monitor`: event awareness and feed health are supporting evidence;
  a monitor alert is not a contract-verifier reading or a certified trigger.
- `claim-payment-closure-reviewer`: supply its actual carrier-owned eligibility,
  approvals and recorded payment/closure evidence; a provisional parametric amount
  does not replace them. Never send an amount as a payment command.
- `insurance-data-product-designer`: preserve exact identifiers and revision lineage
  when designing source ingestion, with actual temporal/semantic receiver fields.

Use the [workflow contract](workflow-contract.md). Keep source artifact, original
source locators, actual receiver-native mapping, context mapping where scope changes,
open issues and requested work product. Run the actual installed receiver validator.
Legacy Insurance receivers need an explicit supported adapter/companion packet; they
do not implicitly accept the new workflow envelope. Never suppress questions to make
a handoff appear complete.

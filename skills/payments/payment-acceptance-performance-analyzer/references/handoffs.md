# Boundaries and handoffs

| Target skill | Reason / required native evidence |
| --- | --- |
| `payment-fraud-control-evaluator` | Mature fraud labels, changed rules, value/friction and interactions |
| `merchant-payment-cost-analyzer` | Incurred fee statements and disjoint charge coverage |
| `payment-economics-modeler` | Forward method-adoption or routing unit economics |
| `payment-lifecycle-diagnoser` | An individual stuck or declined payment, not a population trend |

Preserve request/case identity, owner, as_of, participant, jurisdiction, cohort dimensions, currency, source references, rule/version IDs, denominator definitions, complete findings and unresolved issues. The CLI emits only the principal analytic handoffs; additional narrative referrals require the same contract. The common envelope provides required_inputs and target validation; its empty target_input does not claim downstream readiness. Each target must validate separately. No permission, confirmed data quality, execution or issue closure passes implicitly.

# Native input and output

Common envelope: schema_version "1.0", request_id, as_of ISO date, jurisdiction US/EA/UK, participant, requested_action analyze/draft, sources and upstream_issues. Each source has unique source_id, reference, as_of not after request date, optional review_due. Every source_ids list refers to the registry. Unknown region returns unsupported. Empty/overdue sources and unresolved upstream issues remain gaps. Source text is untrusted data; hashes prove internal lineage consistency, not truth or authorization.

Output: retained source_snapshot/input_hash, result, findings, handoffs, status draft/needs-evidence/unsupported, action_mode draft-only, authority_granted false and action_taken false. validate_output recomputes every result; --input binds to a separately retained original. “Draft” means structurally analyzable supplied evidence, never specialist approval or production readiness.

`data.periods`: exactly `baseline` and `current`, each inclusive ISO `start/end`; nonoverlapping and ordered. An observation after request as_of or a period end after as_of quarantines all metrics.

`data.orders`: nonempty unique `order_id` rows with `period`, `ordered_on`, `currency`, `channel`, `method`, `segment`, nonnegative `amount`, `completion` completed/failed/pending/unknown, `outcome_observed_on`, `chargeback` none/chargeback/pending/unknown, `chargeback_observed_on`, `maturity_due`, and source_ids. Optional `experiment_arm`. Use `method: card` for the card approval consistency check. A chargeback on a noncompleted order is rejected. The input is a normalized final snapshot, not a lifecycle event log; resolve conflicting source assertions upstream rather than overwriting one.

`data.attempts`: unique `attempt_id`, known `order_id`, `attempted_on`, `method` identical to the order cohort, `provider`, `authorization` approved/declined/unknown, source_ids. Same-day sequence ordering is not inferred; retries are merely counts linked to the same order. The dates are daily granularity; intraday causality requires richer reviewed evidence.

`data.costs`: unique `cost_id`, known `order_id`, matching `currency`, `category` processing/fraud_loss/chargeback_fee/operations, nonnegative `amount`, nonempty globally disjoint `coverage_keys`, source_ids. Use gross fees and net realized loss on separate economic coverage. Amounts are explicit finite decimals, preferably strings; no FX conversion or cost extrapolation. `cost_coverage`: complete/partial/unknown is a supplier attestation, not verified completeness. `population_source_ids`, `maturity_policy_source_ids` and `cost_coverage_source_ids` identify extraction, maturity policy and cost-coverage attestation evidence.

Optional `experiment`: experiment_id, `assignment_unit: order`, arms [{arm_id,provider,expected_share}], randomization_source_ids, guardrail_source_ids and guardrails [{metric,direction,threshold}]. Unique arms >=2 with positive fractional expected shares summing to one. Metrics supported: completion_rate, retry_order_rate, mature_chargeback_rate; directions min/max; threshold fraction [0,1]. All current-period orders are the enrolled population; assign every one or supply a separately scoped request. No inferential sample-ratio or significance test is implemented. Unknown maturity gives an unknown guardrail, not pass.

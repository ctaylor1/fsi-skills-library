# Native input schema

Shared envelope: schema_version `1.0`, request_id, as_of (ISO date), jurisdiction `US|EA|UK`, participant (opaque assessed entity), requested_action `analyze|draft`, sources `[{source_id,reference,as_of,review_due?}]`, upstream_issues `[{code,message,source_ids?}]`, and data below. All source_ids reference registered IDs. Dates are Gregorian ISO dates; amounts are decimal strings or integers, never binary floating point or booleans. Null preserves missing evidence. Every record described as sourced requires a nonempty source_ids list. No embedded secret or card-authentication data.

Input validates shape and reference identity. Analysis detects applicability, economic consistency and missing evidence. Output contains source_snapshot, recomputation hash, result, findings, unresolved upstream issues and draft-only handoffs. Always validate output with the independent input path; rehashing arbitrary source changes is not authentication.

## data

Required text: use_case, participant_ref, origin_jurisdiction, destination_jurisdiction, source_currency, destination_currency, comparison_currency, accountable_owner. Currency codes have three uppercase characters. principal is positive in source_currency. window_start and window_end are inclusive ISO decision/quote dates; dates do not establish operational cutoffs. Jurisdiction codes use the envelope's analysis labels; actual countries, entities and laws belong in the source applicability review.

role_assignments is a nonempty sourced list of `{entity_ref,role,responsibility,source_ids}`. role is issuer, holder, intermediary or custodian. One entity may have several evidenced roles; duplicates of the same entity/role are rejected. A self-custodian is explicit. The assessed participant requires its own role.

options has exactly two sourced rows, one `type: stablecoin` and one `type: fiat`. Each needs unique option_id, instrument_ref, provider_ref, quote_basis_ref, availability_status (production|pilot|research|unknown), costs_complete boolean, delivered_amount (nullable fiat amount in destination_currency), evidence object and applicability object. A stablecoin row also requires asset_ref, chain_id, issuer_ref and custodian_ref. These are supplied opaque identities, not ticker-only proof or addresses to transact with.

quote_binding is exactly `{principal,source_currency,destination_currency,comparison_currency,window_start,window_end}` copied from the supported quote's terms. Different lexical decimal principal representations must be normalized by an accountable mapper before analysis. A binding mismatch suppresses total cost. A cost is an explicit absolute all-in amount for this same principal/window, not basis points. costs requires exactly these keys, each nonnegative or null: network, provider, fx, onramp, offramp, redemption, custody, liquidity, operations. An evidenced zero is permitted; no default zero exists. Categories are disjoint: fx is only the separately costed FX charge/spread, not converted principal; principal is not a fee. quote_basis_ref must explain conversions to the comparison currency and nonoverlap. costs_complete declares the supplied coverage; the helper cannot discover hidden fees. No local FX conversion or amortization.

evidence contains reviewed nonempty reference strings: availability, provider_counterparty, legal_applicability, sanctions_aml, liquidity_access, failure_recovery, economic_finality. Stablecoin adds issuer_reserves, redemption_rights, custody_control, chain_finality, freeze_fork_bridge, holder_rights. Missing fields produce gaps. Each reference is supported by the option's registered source_ids. Record chain confirmations and legal finality separately; no universal number is imposed.

applicability needs profile_id, version, owner, reviewed_on, review_due, jurisdictions list covering origin/destination, participant_roles list covering this participant, instrument_refs covering the exact option instrument_ref, and source_ids. Stablecoin reviews additionally require asset_refs and chain_ids covering the exact named asset and chain. The full window must be within review coverage. References must address effective rules, provider access, actor obligations and instrument classification; date checks alone do not determine law. Review owners are responsible for specialist acceptance.

## result

Options show known all_in_cost or null and all unresolved_conditions. fiat_minus_stablecoin_cost is computed only for two known totals and equal delivered fiat amounts; positive means the supplied fiat cost is higher. This is an arithmetic comparison even if risk conditions remain unresolved, never an adoption recommendation. Role assignments and corridor persist. All approval, settlement, peg, redemption and legal-permission flags remain false.

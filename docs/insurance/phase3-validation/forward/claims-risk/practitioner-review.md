# Independent insurance Phase 3 forward review: claims and risk

Seven packages; 24 fresh synthetic practitioner scenarios, with inputs and expected outcomes frozen before native execution. Original files are immutable in this evidence bundle. No packaged tests, evaluations, fixtures, goldens or prior audits were read to design these cases. Only package SKILL, schema, method, source/control, handoff and shared contract documentation informed case design. Runtime implementation was inspected only after outputs exposed defects.

This is independent synthetic behavioral review, not qualified insurance practitioner sign-off, legal adoption verification, source authentication, medical review, model validation or production acceptance. The explicit US-TEST/internal profiles and named synthetic reviewers are test assertions, not actual authority. Public-source links in the packages were read as contextual references; their live legal applicability was not independently audited.

- `freeze-manifest.json` and `.sha256`: original 24 cases, 48 input/expectation hashes, timestamp, and exact documentation/runtime hashes at design freeze.

ORSA entries in this check set explicitly use mapping-only runs. The 48 frozen-file integrity checks are included in the 420 total.
- `repaired-practitioner-checks.json`: final 420/420 checks pass, combining the four repaired benefit replays, three explicit ORSA mapped cases and 17 original cases. Every check identifies which run it uses. This does not claim all 24 inputs were replayed.
- `benefit-replay-integrity.json` and each benefit case's `repaired/`: exact unchanged-input and unchanged-expectation hashes, repaired outputs, command logs and runtime hashes. Only `domain.py` changed between the original and repaired benefit runtime snapshots.

Original native execution attempted all three commands for each case (72 attempts). Twenty-three produced native artifacts and passed all three scripts. The Boolean-money case was correctly rejected at input and calculation; the third attempt rejected the calculator error JSON, not an insurance artifact. Three additional ORSA mapping-only runs passed all nine commands. Native validator success was never treated as proof of business correctness.

## Defects established on original frozen inputs

1. **Unsupported benefit method still emits dependent period calculations.** `benefit-unsupported-monthly-method` supplies a monthly-income-percentage method. Overall status is needs-data and aggregate/capped totals are null, but the period output still computes August 19 eligibility, 13/18 eligible days and 2,730/3,780 gross plus 2,400/3,600 net using the unsupported daily convention. Those dependent calculations must be withheld.
2. **Incomplete benefit offset inventory becomes known zero at period level.** `benefit-unknown-offset-inventory` sets `offset_inventory_complete=false` and supplies an empty inventory. Overall status is needs-data and aggregate/capped totals are null, but period offsets become zero and net amounts become 2,730/3,780. Period offset and dependent net fields must remain unknown.
3. **ORSA native schema does not name the implemented review field correctly.** The schema stated capital/liquidity rows require `reviewer`; implementation requires `reviewed_by`. The three original inputs therefore withheld every surplus under scenario-measure-identity findings. Mapping only the field name (retaining every supplied reviewer value) restores expected arithmetic. The original failed inputs/runs remain preserved and are not characterized as unchanged-input successful replays. Documentation correction is with the root reviewer.

## Disposition

**Complete for this bounded synthetic review.** Both benefit defects were repaired by the package author and independently closed by replaying all four original benefit inputs unchanged. All four native input/calculation/output pipelines pass, the previously incorrect dependent fields are now null, supported positive arithmetic is unchanged, and conflicting observations still withhold dependent scenarios. All original input and expectation hashes remain identical. Final combined review is 420/420 assertions across 24 logical practitioner scenarios; 48 of those assertions verify original file integrity.

The root reviewer corrected ORSA schema documentation to explicitly name `reviewed_by`; the three successful ORSA runs remain clearly identified as naming-only adaptations, not unchanged-input success. Original schema-authored failures remain in the evidence bundle. No open defect remains from the reviewed cases. This closes the tested behavior, not untested package behavior, professional acceptance, source truth, current legal applicability or production readiness.

Total native command attempts: 93 (72 original, 9 naming-only ORSA, 12 unchanged benefit replay). Ninety exit successfully; three expected nonzero exits belong to the Boolean-money case (input rejection, calculation rejection, and subsequent rejection of the calculator error payload). Thirty valid native insurance artifacts were produced across original/adapted/repaired runs; the Boolean error JSON is not an insurance artifact. There are 24 original input documents, 24 original expected-result documents, and three separate mapped ORSA inputs. No repository files were edited by this reviewer.

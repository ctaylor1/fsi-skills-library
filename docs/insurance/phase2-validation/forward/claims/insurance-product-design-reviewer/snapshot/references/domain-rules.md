# Native method and limits

Interpret `features` as promises with wording and operating owners. The script links feature IDs to supplied source references and surfaces failed/unknown claims-operation tests. `requirements` are explicit reviewed assertions classified as actuarial, wording, distribution, operations, or filing. Presence does not prove a requirement is legally sufficient. Require a reviewed profile and all five review scopes, retaining non-required assertions and unsatisfied requirements. The output is a traceability matrix and issue queue, never a launch approval. Practitioners must examine actual customer value, exclusions, underwriting appetite, claims handling, distribution incentives, affordability and operational feasibility in the source documents; structured statuses summarize that review and cannot replace it.

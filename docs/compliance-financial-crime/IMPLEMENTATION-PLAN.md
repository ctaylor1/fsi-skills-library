# Compliance and Financial Crime implementation plan

The September 21, 2026 architecture review proposed 36 workflow skills and one router,
with existing specialist owners retained in adjacent domains. The user authorized
Phase1 with “implement phase 1 now” and Phase2 on October 3, 2026 with
“implement the next phase now.” Phase3 was separately authorized on October4,2026 with the same request. The full target portfolio is in
`catalog/compliance-financial-crime-capabilities.json`; planned rows are not installed
or accepted capabilities. Future work requires its own authorization.

## Phase1 — structure, correctness and control boundaries

Status: implementation and bounded software verification completed 2026-09-21. See
[implementation](PHASE1-IMPLEMENTATION.md) and [verification](phase1-validation/README.md).
Professional/source/institutional acceptance remains open.

- Preserve existing unrelated work and every original package's disposition.
- Repair missing-to-benign conclusions, silent methodologies, unsupported legal
  defaults, source fidelity, approval/readiness and execution claims in all 15 packages.
- Introduce one declared-intent router covering all 27 reviewed requests, showing
  planned, bounded, unknown-installation, missing-context and action-boundary states.
- Rename customer/ownership/EDD/sanctions/preclearance packages to their actual jobs;
  move generic privacy assessment to Data, AI & Model Governance with privacy ownership.
- Rename the current monitoring code to a transitional scenario evaluator; pin its
  replay method as a shared component. Full case investigation remains Phase2.
- Establish source/status, role/action, confidentiality, detached native output and
  producer/receiver handoff contracts. Reject unsupported schemas/context changes.
- Preserve legacy identifiers through migrations, update active cross-domain routes,
  and maintain catalog regeneration and portable pinned resources.
- Verify meaningful domain regressions, independent forward cases, aliases/routes,
  native tamper/unknown propagation, isolated installation and repository compatibility.

Exit: accurate scope for all 15 original jobs, no supported favorable result from
material missing evidence, critical findings covered by substantive regressions,
correct native input/output validation, explicit method gaps and recorded verification.
Technical checks are not legal approval, source authentication or deployment acceptance.

## Phase2 — foundational professional workflows (implemented; bounded verification complete)

Status: implementation and bounded software verification completed 2026-10-03. See
[implementation](PHASE2-IMPLEMENTATION.md) and [verification](phase2-validation/README.md).
Practitioner, legal/source/institutional and deployment acceptance remain open.

The implementation includes program design/effectiveness, applicability, obligation mapping, institution risk,
business-change review, full CDD/EDD and case investigation, sanctions exposure,
reporting/notification lifecycles, conduct outcomes, testing and remediation, plus
governance, ethics and external-promotion jobs with distinct native scope.
Phase2 comprises 19 new packages and substantive CDD/EDD modes, recorded in
`catalog/compliance-financial-crime-phase2-capabilities.json`. External promotion
ownership moves to the cross-sector reviewer; Capital Markets retains supervision,
archive and internal-communications support. No empty placeholder skills.

Dependencies: Phase1 contracts, reviewed institutional facts/methods, current legal
profiles and practitioner owners. Exit: distinct triggers/outputs/owners, reviewed
sources, tested native methods and declared supported profiles. Risks: shallow broad
skills, wrong applicability and conflation of operations with independent assurance.

## Phase3 — modernization and effectiveness (implemented; bounded verification complete)

Status: four domain native methods and scoped technology composition implemented 2026-10-04. See [implementation](PHASE3-IMPLEMENTATION.md), [composition](MODERNIZATION-COMPOSITION.md) and [validation](phase3-validation/README.md). Professional/institutional/source and production acceptance remain open.

Screening/monitoring evaluation and design, case QA, data reconciliation, graph/entity
resolution, identity adapters, real-time requirements, vendor evidence, program economics
and controlled copilots. Reuse existing architecture, AI/model and automation skills.

Dependencies: lawful data/engine access, representative populations, mature labels or
explicit ground-truth limits, independent benchmarks. Exit: supported data methods,
source/audience evaluations, resilience and separately accepted execution controls where
needed. Alert reduction and faster closure alone do not demonstrate effectiveness. The implemented methods review supplied data/identity/engine observations and requirements; operational algorithms, enterprise connectors and separately accepted execution controls are not bundled.

## Phase4 — advanced/specialized scope (pending)

Cross-border investigations, trade/PF, correspondent banking, complex arrangements,
digital assets/stablecoins, market surveillance and sector/jurisdiction overlays.
Specialized requirements move earlier when intended users already face the exposure.

Exit: supported activity/entity/jurisdiction matrix, conflict cases, specialist acceptance,
source owners and sustainable update processes. Create a standalone job only with a
distinct reusable trigger, artifact and accountable owner.

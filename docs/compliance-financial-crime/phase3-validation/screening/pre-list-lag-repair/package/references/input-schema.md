# Native input schema

The native object is `sanctions_screening_control_review`; the method accepts only the exact top-level fields `request_id`, `object_id`, `object_type`, `as_of`, `knowledge_cutoff`, `workflow`, `sources`, `data`. The bundled [foundation contract](foundation-contract.md) defines context, audience/classification, detached source registry, chronology and unresolved-issue retention. No top-level approval or execution field is supported.

Every domain field except each collection's local record ID is exactly `{ "value": VALUE, "source_refs": [REF], "fact_ids": [FACT] }`. Each known consequential value must match every cited fact exactly in value and JSON type. Null with explicit arrays is valid partial evidence; it produces a gap. Empty arrays do not support a claim. An unknown string is not a decimal, timestamp or enum; use null. Record IDs are local join keys; source-bound review scopes and case/feed/list/version claims bind their professional meaning.

All fields below are required; extra fields, duplicate JSON keys, duplicate record/list/reference IDs and out-of-scope observations are rejected. String lists are distinct identity arrays. Exact decimal strings use nonnegative base-10 notation without exponent, sign or surrounding space (`"0.5"`, `"2.000001"`); rate limits must be <= 1. JSON numeric decimals and booleans are rejected. Times use explicit RFC3339 offset, optionally up to six fractional-second places, and normalize to UTC.

| Object / collection | Required claims |
| --- | --- |
| review | window_from/to (instants); regimes, population_ids, feed_ids, list_ids, testset_ids, control_ids, required_fields/scripts/test_dimensions (string lists); maximum_list_update_lag_seconds, maximum_latency_seconds (decimal strings); maximum_false_positive/negative_rate (decimal rate strings); mandate_owner (string); mandate_type (operational-qa, second-line-monitoring, independent-testing); population_grain (screening-input-record-id) |
| configuration | engine_id/version, configuration_version, vendor_reference/version, normalization_rules, transliteration_rules, matching_method, threshold_description (strings); effective_from/to (instants); fields/scripts (string lists) |
| feeds [feed_id] | population_ids, received_ids, screened_ids, fields, scripts (string lists); window_from/to (instants) |
| lists [list_id] | regime, expected_version, loaded_version (strings); published_at, effective_at, loaded_at (instants); expected_entry_ids, loaded_entry_ids (string lists) |
| testsets [testset_id] | version, label_reference, label_version, label_scope, selection_method (strings); case_ids, represented_dimensions (string lists); labels_as_of (instant); accepted_for_measurement (boolean) |
| tests [test_id] | case_id, testset_id/version, feed_id, list_id/version, engine_id/version, configuration_version, dimension, input_script (strings); input_fields (string list); expected_detection (expected-alert or expected-no-alert); observed_detection (alert, no-alert or error); observed_at (instant); latency_seconds (decimal string); evidence_complete (boolean) |
| controls [control_id] | dimension (population, feed, list, field, transliteration, matching, configuration, vendor, resilience, latency); requirement, procedure, finding (strings); population_ids (string list); observed_at (instant); outcome (pass, fail, unknown); evidence_complete (boolean) |

`data` contains exactly review, configuration, feeds, lists, testsets, tests and controls. Known collection IDs exactly match declared review arrays. Feed populations are disjoint subsets of review population; received/screened IDs lie in their feed. Test feed/list/testset and case IDs lie in declared collections/testset scope. A duplicate case observation is malformed even when its record ID differs. Controls use subsets of the review population structurally, but complete control coverage needs the exact entire supplied review population. Unknown substantive scope is retained rather than fabricated.

The [machine schema](input-schema.json) describes shape; the executable `scripts/validate_input.py` additionally enforces joins, uniqueness and scope. See frozen [complete](../evals/files/input_complete.json), [partial](../evals/files/input_partial.json) and [invalid](../evals/files/input_bad.json) fixtures, all synthetic. Scope, label/observation chronology and measurement eligibility are detailed in [domain rules](domain-rules.md).

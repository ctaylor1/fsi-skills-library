## Evidence, professional boundaries and portability

The new foundation contract binds actual native object/context, assessment date,
knowledge cutoff, institutional responsibility and source access. Consequential
claims resolve against exact supplied source facts, including value type; unsupported,
conflicting or unavailable evidence withholds dependent findings. No default legal
profile, review cadence, risk weight, materiality threshold or approval is inferred.
Claim locators retain native pointers, source IDs, fact IDs and consistency states
without embedding the raw original. Institution methods and evidence remain supplied,
unverified records. Exact matches are not source truth or legal sufficiency.

Domain methods keep important distinctions visible: turnover versus proceeds;
identity matches versus restrictions; proposals versus effective obligations;
documented design versus observed operation; cohort denominators versus coverage;
QA versus independent testing; a revised document versus demonstrated remediation.

Independent cases also tightened evidence grain and chronology. CDD rejects repeated
receipt provenance; substantive EDD requires source-bound economic-event identity and
an explicit applicable additivity basis before reporting a total. Repeated documents
about one identified event count once; conflicting event evidence withholds the total.
Customer-outcomes proportions require compatible source-bound customer units, and
threshold comparisons use exact supplied decimal strings rather than JSON floating
numbers. An approval after first use cannot cover the preceding promotion interval;
a later unresolved failed retest prevents remediation-criterion sufficiency. Known
information-barrier scope mismatches remain visible alongside missing facts, embedded
list changes need their own mandate, and notification obligations retain independent
states and immediate timing without inventing a due date.

Native facts, conditional method support, analyst hypotheses, unresolved evidence and
human decisions are separately labeled. All results remain drafts, require human
review, and record no approval or execution.

The common adapter adds 19 domain object schemas and two customer modes to 11
preserved original schemas. Actual installed producer/receiver validators run against
detached inputs. Foundation handoffs preserve full source facts, cutoff, exact context,
classification/audience and unresolved issues. Changed evidence under the same source
version, invented mapping references and dropped issues are rejected. Four original
native-only schemas remain unsupported; cross-context/audience and foundation-to-legacy
projections need separately reviewed adapters. An investigator-to-SAR conversion is
not claimed. Bundled helper/reference copies and per-package file manifests are pinned;
packages run independently without runtime sibling imports.

## Acceptance and retained work

Validation proves bounded software behavior, reconstruction, routing and isolated
execution on synthetic supplied data. It does not prove semantic extraction from
institutional records, complete laws or rule packs, real-world decision quality,
independence, privilege, disclosure legality, approval or production readiness.
Deployment requires accountable practitioners, approved institution methods, lawful
sources/access, confidentiality controls, live integrations and separate operational
authority where applicable. The external source workbook remains unreconciled.

Existing unrelated work and Phase1 validation archives are preserved. This task does
not commit, push, merge, release, file, notify, publish or mutate operational records.

# Independent Payments Phase 4 router evaluation

The evaluator read the public router SKILL, registry intent names, native CLI interface and the original architecture request list. No package evals, regression tests or golden outputs were read. The original architecture itself contains planned ownership examples; final routing judgments also used public installed skill responsibilities and current module boundaries. Expectations were frozen before invoking the CLI. This exercises agent-authored natural-language interpretation followed by structured routing; route.py does not claim to classify language automatically.

Final pass: 18 original natural requests plus 23 supplemental cases, 85 native routing/validation calls and 303 assertions passed. The original broad orchestration request correctly retains a participant clarification instead of selecting merchant or bank ownership arbitrarily. Concrete merchant and bank examples select different appropriate leads. Other incomplete requests keep missing context and target native validation requirements.

Supplemental cases cover Pix, UPI, Interac, explicitly unprofiled Japan/Zengin, corridor liquidity, wallet/mobile money, advanced platform responsibilities, commercial cards, agent credential/platform modes, distinction between stablecoin controls and settlement assessment, orchestration by participant, merchant and issuer disputes, refunds, payout explanation, phone scam ownership, unavailable target inventory, unknown intent, execution rejection, and preservation of core-bank mode. Authority flags stay false. Tampered authority outputs are rejected by route recomputation.

The first expectation run had two evaluator naming errors: payout explanation and payment-fraud investigation were assigned guessed package names. Public installed skill descriptions confirmed the intended workflow owners are payment-settlement-reconciler and payment-fraud-and-scam-investigator. The role/mode expectation was unchanged; no implementation correction was needed. Original expectations/results are retained in initial-expectation-run/, and expectation-correction.json records the exact resolution. The current frozen-expectations/results/summary files contain the verified installed names.

Router, registry, common helper and public SKILL hashes were unchanged during both observed runs. Final source hashes are retained. This is bounded routing/intent-mapping evidence, not target-domain specialist acceptance, live regional compliance, provider access or production execution readiness.
